# Architecture Review
Generated: 2026-09-21T18:23:03.929Z

## Summary
The codebase is a small React/TDS mini-app with a sensible layering: pages, components, hooks, and lib. Pure logic in lib is well separated from UI. The main problems are duplicated SDK/haptic guard code, two competing type systems (`contract.ts` against `types.ts`), and leftover scaffolding and dead code.

## Issues
### Critical
- [structure] Two conflicting type definitions exist. `lib/contract.ts` (auto-generated) declares `RouteState` as a string union, plus `Fortune`, `Alert`, `Category` and `FortuneType` with shapes different from the real ones in `lib/types.ts`. `types.ts` declares `RouteState` as an interface, `FortuneType` as a character record and `AlertItem`. Only the `getCharacterImageFn` and `getFortuneMessageFn` types are consumed, by `fortuneTable`. Contract types like `useAppDataFn` and `useContentNoticeFn` do not match the real hook signatures, which use `loading`, `open` and `description`. — Files: src/lib/contract.ts, src/lib/types.ts, src/hooks/useAppData.ts, src/hooks/useContentNotice.ts / Fix: Remove `contract.ts` or reconcile it with `types.ts`. Keep one source of truth and delete the unused contract types.

### Suggestions
- [consistency] Import styles and quote style are mixed. `Amount` and `CountUp` use relative `../lib/utils`, while most files use the `@/` alias. Components use double quotes and semicolon-terminated single-quote style varies by file, with `App`, hooks, lib and pages using single quotes. `PageShell` and `ScreenScaffold` use relative imports. — Files: src/components/Amount.tsx, src/components/CountUp.tsx, src/components/ScreenScaffold.tsx, src/components/SummaryHero.tsx / Fix: Standardize on the `@/` alias and add Prettier/ESLint rules to enforce quotes and imports.
- [duplication] `CATEGORY_IDS` and `ALL_CATEGORIES` are defined separately in `stats`, `Input` and `fortuneEngine`. Alert category labels duplicate `CATEGORY_LABEL` with shorter text. `useAppData` duplicates the `STREAK_LOOKBACK_DAYS` and `RECORD_LOOKBACK_DAYS` 90-day constants. Both `History` and `Settings` also define the same constants. — Files: src/lib/stats.ts, src/pages/Input.tsx, src/lib/fortuneEngine.ts, src/lib/alerts.ts, src/pages/Settings.tsx, src/hooks/useAppData.ts / Fix: Export `CATEGORY_IDS` from `types.ts` and share the retention and lookback constants from one config module.
- [structure] `FloatingTabBar` and `TabLayout` are wired up in `App.tsx`, and `TabLayout` is defined inline there. Two ad components (`AdSlot`, `AdSection`) and two ad/payment SDK wrappers sit beside generic UI components. The `TossRewardAd` component imports CSS from `styles`, while every other component uses inline styles, so styling is inconsistent. `App.tsx` uses a pages directory with a `__TdsGallery` dev page. — Files: src/App.tsx, src/components/TossRewardAd.tsx, src/components/AdSlot.tsx, src/components/TossPurchase.tsx / Fix: Group SDK wrappers into `components/toss/` or `integrations/`, move `TabLayout` to `components/`, and choose one styling approach.
- [circular_dep] No true cycles were found. However, `lib/fortuneTable` imports types from `contract`, and `contract` in turn describes `types`. `stats` depends on `storage`, and `computeFortune` depends on both, so the layering is fine but `fortuneTable` mixes data with contract-typed functions. — Files: src/lib/fortuneTable.ts, src/lib/contract.ts / Fix: Keep `getCharacterImage` and `getFortuneMessage` in a separate module from the static tables to keep the data layer pure.
